# Changelog

All notable changes to **FRAME/12** are documented in this file.

## [Unreleased]

### Fixed

- **`/components/exposure-scrubber` accessibility (found on frame12.dev after the #39 deploy):** the page's demo and guide headings were `h3` directly under the page `h1` (axe `heading-order`); they are `h2` now, like the page's other sections. The light and dark previews rendered two ExposureScrubber panels with the same accessible name (axe `landmark-unique`); each preview's label now names its theme. `site-verify` runs its axe and grammar sweep on `/components/exposure-scrubber` and the three ink pages too; on that page the frame panel's `CURRENT CUT / F-xx` label is checked as a frame label and every other cut must still be sequential.
- **Flaky browser tests:** the registry GhostWire mount-pose check measured one animation frame after `createRoot().render()`, which commits asynchronously; on loaded CI runners the line did not exist yet (`firstFrameOffset: 0`, `finalOffset: -1`). It now renders with `flushSync`, waits for the element, and waits for the on-twos reveal to settle (3 s deadline) instead of fixed 480/560 ms windows. Under DevTools CPU throttling the old check failed 16/20 (4×) and 20/20 (10×, 20×); the new one passes 60/60. The site developer-console SLO check's root cause (a late refocus from the retry step) was fixed on `main` in lbrodie11/frame12#35; on top of that, its 24h/7d/30d reads now wait for each expected state (`waitForFunction`, 3 s) instead of reading immediately after a click, and a failure reports where focus went.

### Added

- **Ink: line art drawn on twos (F12-14).** Three opt-in registry items (not in the full kit or the `@/components/frame12` barrel, so nothing changes for existing users):
  - **`InkStroke` (`registry/ui/ink.tsx`, `/r/ink-stroke.json`):** one `<path pathLength="1" stroke="currentColor" fill="none">`. Drawing is pure CSS: `stroke-dashoffset` 1 → 0 with `steps(poses, jump-start)` over `poses × var(--f-pose)` (`poses` 1–24, default 6); `linear` at tempo `ones`; no animation at `cut`. At rest no dash properties apply, so a finished closed mitered path is pixel-identical to a plain one (no seam). Weights `pencil` / `detail` / `frame`. `inkPencil(segments, seed?, wobble?)` (`registry/ui/ink-pencil.ts`, re-exported from `ink.tsx`) draws deterministic pencil construction lines from a seeded mulberry32 PRNG (no `Math.random`); chained segments join into one subpath so they draw over the beat (SVG restarts dashes per subpath).
  - **`InkReveal` (`registry/ui/ink-reveal.tsx`, `/r/ink-reveal.json`):** inks a `Panel`/`PanelPair` frame (6 poses), lands the cut number (1 pose), then shows the content in one cut. The stroke starts top-left, or top-right under `dir="rtl"`.
  - **`InkSequence`, `InkBeat`, `InkLand` (`registry/ui/ink-sequence.tsx`, `/r/ink-sequence.json`):** one state machine (`rest` default/SSR, `playing`, `scrubbing`, `still`). Beats chain by CSS `animation-delay` sums; `onEnd` comes from the `animationend` of a root clock animation lasting every beat; Stop returns to the finished drawing; a tempo or reduced-motion change mid-play finishes it. `scroll` attaches `animation-timeline: view()` after mount where supported (native scroll, no listeners, no `scroll-snap`).
  - **One play, one draw:** a play is consumed when it finishes or when motion resolves to `cut` mid-draw; re-enabling motion never replays it (only a new `false → true` change of `play` does). `InkReveal` calls `onEnd` exactly once per reveal, also around a `PanelPair`. An `animationend` that arrives after `play` has changed still counts for the play it finished (the A/B keyframe name says which), and a superseded play's late end never ends a newer one. Under forced colors and in print the drawing shows finished while a play in flight still ends and calls `onEnd` (its animated properties are pinned with `!important` instead of removing the animations); the fallbacks only touch the reveal's own frame, cut and body, never animations of content inside a revealed panel.
  - **Never on load:** primitives draw only when `play` changes after mount. `@frame12/lint` 0.3.0 (prepared, not published) adds the `ink-autoplay` rule.
  - **Tokens:** `--f-stroke-pencil` (1px) and `--f-stroke-detail` (1.5px) in `@frame12/tokens` (DTCG `stroke.pencil` / `stroke.detail`) and `frame12.css`. (`--f-ink-2` is already the secondary ink colour, so the width scale is named by use.)
  - **`Panel` (additive):** the measured frame polygon carries `pathLength="1"`. The SSR `viewBox` polygon (`vector-effect: non-scaling-stroke`) is never dashed.
  - **Tests:** `registry/tests/ink.mjs` (poses and holds at 60/120 Hz sampling, ones/cut, zero `requestAnimationFrame`/`setTimeout`, SSR/hydration rest, pixel identity light/dark, SSR polygon, RTL, resize mid-reveal, Play/Stop/rapid toggles/tempo and reduced motion mid-play, contrast at every pose, pencil determinism server = client) and the ink sequence in `flash-safety.mjs` at `twos` and `ones`.

- **Tempo: one motion preference for the whole system (F12-08):** `auto` (AUTO, each component's own motion), `twos` (12, on twos), `ones` (60, smooth) and `still` (0, no non-essential motion). An accessibility feature first, a style choice second.
  - **`registry/hooks/use-tempo.ts` (`/r/use-tempo.json`, new):** `type Tempo`, `TEMPOS`, `isTempo`, `normalizeTempo`, the pure `resolveMotion({ base, tempo, ancestorStill, reduced })`, `TempoContext`, `useTempo()`, `useResolvedMotion(base)` and `useReducedMotion()` (moved here; `use-on-twos` re-exports it, so existing imports keep working). Precedence: OS reduced motion → cut; `still` here or in any ancestor → cut; an explicit/variant/default `cut` stays cut (tempo never turns motion on); `twos` → stepped; `ones` → smooth; `auto` → the component's own motion. Invalid values (a stored `"fast"`) read as `auto`. Pointer tracking, drag, scroll, typing and focus movement are never stepped or delayed.
  - **`TempoProvider` (`registry/ui/tempo.tsx`, `/r/tempo.json`, new):** controlled (`value`/`onChange`) or uncontrolled (`defaultValue` + `storageKey`, persisted in `localStorage` inside `try/catch`, synced across tabs); `value` wins over `defaultValue` with a development warning. Nested providers set `twos`/`ones`/`auto` for their subtree while `still` from any ancestor cannot be undone. Renders a layout-neutral `display: contents` wrapper (or `asChild`) with `data-f12-tempo` and, when the tempo forces a mode, the matching `f12-m-*` class.
  - **`TempoControl` (`registry/ui/tempo-control.tsx`, `/r/tempo-control.json`, new):** a `<fieldset>` + `<legend>` ("Animation tempo") with four native radios in the segmented appearance (arrows move and select; Tab is one stop; names such as "12, on twos"; targets ≥ 44×44). Under OS reduced motion it shows `0 · your system setting` and keeps the stored choice selectable; without a provider it renders disabled with an explanation. `SegmentedControl` is unchanged.
  - **Resolution in JS, not CSS overrides:** `useOnTwos` (and so `useCountUp`, `Metric`, `ToneSpark`, `ToneAreaChart`) resolves its `motion` through the tempo; `Sheet` emits the resolved `f12-m-*` class; `GhostWire` and the blocks' reveal scrolls use the resolved mode. A change to cut mid-tween settles immediately; switching back animates nothing until the next real state change. `GhostWire` now tracks its target while cut, so turning motion back on no longer replays the draw-on.
  - **First paint:** one CSS rule, `html[data-f12-tempo="still"]` (and its `.f12-m-stepped` / `.f12-m-smooth` descendants) takes the `.f12-m-cut` values, so a stored `still` never shows motion before hydration. It only ever turns motion off. `TempoProvider` with a `storageKey` keeps the attribute current.
  - **Registry:** `use-tempo` is a `registryDependency` of `use-on-twos` and of every item that uses it (`sheet`, `panel`, `panel-pair`, `metric`, `ghost-wire`, `tone-area-chart`, `tone-bar-list`, `tone-spark`, `frame12-base`), so `npx shadcn add @frame12/metric` installs it; the complete kit includes the new files. `scripts/sync-workspaces.mjs` now syncs every `registry/hooks/*.ts`.
  - **No behavior change without a provider:** SSR HTML, settled DOM and 60 Hz animation timelines of all motion consumers are identical to the pre-tempo registry source (main at `0e19283`, extracted from git and captured in the same browser by `registry/tests/tempo.mjs`).
  - **Tests:** `registry/tests/tempo.mjs` (resolver table, no-provider baseline, provider modes/storage/nesting/`asChild`/cross-tab/no `matchMedia`, control keyboard/names/disabled/reduced/axe/320–400% zoom, live reduced-motion safety, propagation, performance, metric-only install on React 18.3 and 19) and `registry/tests/flash-safety.mjs` (approximates WCAG 2.3.1 with deterministic seeking; not a certification).
