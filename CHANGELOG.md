All notable changes to **FRAME/12** are documented in this file.

## [Unreleased]

### Added

- **Navigation Continuity on frame12.dev (F12-12):** Back, contextual return links and focus now land where the visitor was.
  - **`onSectionChange` on tabbed blocks (additive, optional):** `DeveloperConsole` (`(section: ConsoleSection) => void`) and `WorkspaceSettings` (`(section: SettingsSection) => void`) call it once with the new section after every internal section change (tab, breadcrumb, empty-state, cross-link or validation jump), never on mount and never twice under `<StrictMode>`. Without a callback the rendered markup is byte-identical to `0.2.0` (React 18 SSR snapshot in `registry/tests/block-section-callback.mjs`). Blocks stay router-agnostic (no `next/*` imports in `registry/`).
  - **Tab state in the URL:** `/blocks/developer-console` and `/blocks/workspace-settings` read a validated `?section=` (unknown values fall back to the default tab) and mirror tab changes with `history.replaceState`, so tab switches add no history entries, tabs survive Back/reload/sharing, and the server renders the right tab (works without JavaScript; the page height is right before first paint so native scroll restoration lands correctly). The default section omits the parameter. `AnalyticsDashboard` has no tabs and is unchanged.
  - **Contextual return links with no open redirect (`site/src/lib/return-context.ts`):** dependency and catalog links carry an origin *token* (`?from=block.developer-console.request-logs.dependencies`, `?from=catalog.<group>`), parsed with a strict grammar against allowlists; return targets are built from a table, so external or arbitrary URLs cannot be expressed. Component detail pages show a `Blocks / Developer Console / Dependencies` trail, a primary `← Back to Developer Console · Dependencies` link and a secondary `Browse all components` link; direct opens keep the plain `← All Components`.
  - **Focus restoration on Back/Forward only (`site/src/lib/history-focus.ts`):** activating a dependency or catalog link (opted in with `data-f12-return-focus`) merges `{ f12Focus }` into the current entry's `history.state` (Next.js's `__NA` / `__PRIVATE_NEXTJS_INTERNALS_TREE` keys preserved); any other in-site link navigation clears it, and modified (new-tab) clicks record nothing. A `popstate` return waits for the element, then focuses it with `preventScroll` only if it is on screen, falling back to the section heading (`tabIndex={-1}`) and otherwise doing nothing. Fresh navigations and reloads never move focus.
  - **Route ownership table (`site/src/lib/nav-ownership.ts`):** the primary nav marks the exact page `aria-current="page"` (with an underline text cue) and the owning section of a child page `aria-current="true"` (e.g. Agents on `/experiments/agent-approval`, Components on `/components/<slug>`).
  - **Mobile nav overflow cue:** a screentone edge strip with a `‹`/`›` chevron appears only at edges that still have links beyond them; a focused nav link is kept fully visible and clear of the cue.
  - **Canonical URLs:** component detail and block pages declare `<link rel="canonical">` without `from` / `section` parameters.
  - **Tests:** `site/tests/navigation-continuity.mjs` (round trips by mouse and keyboard, Back/Forward chains, direct open/reload/new tab, hostile tokens, missing focus targets, history hygiene, ownership, 320px and 200% zoom nav, reduced motion, no-JS, canonical, axe light/dark) in Chromium, Firefox and WebKit; `site/tests/unit.mjs` (token parser and ownership table); `registry/tests/block-section-callback.mjs` (React 18.3 and 19).

### Changed

- **`WorkspaceSettings` unsaved-changes click guard ignores same-page links (F12-12):** a link to the same pathname (only the query or hash differs, e.g. a `?section=` tab URL) no longer opens the "Unsaved Configuration Changes" dialog, because the block stays mounted or restores its cached draft. Links to other pages are still guarded, and hard reloads are still covered by `beforeunload`.
- **Site block pages render per request (F12-12):** `/blocks/developer-console` and `/blocks/workspace-settings` are now dynamic (their client code moved to `showcase.tsx` beside each `page.tsx`) so `?section=` is rendered server-side. Component detail pages stay statically generated and read `?from=` on the client.
- **Token Consumption & Internal Motion Custom Property Namespace (`registry/styles/frame12.css`):**
  - Replaced `2.5px` stroke/border literals across `registry/styles/frame12.css` with `var(--f-stroke)` (while `--f-pose` and `--f-fps` remain reference-only CSS custom properties on `:root`).
  - Renamed the 6 internal `.f12-m-*` transition/animation helper variables in `registry/styles/frame12.css` from `--f-*` to `--f12-*` (`--f-rng-ind-transition` → `--f12-rng-ind-transition`, `--f-switch-thumb-transition` → `--f12-switch-thumb-transition`, `--f-skeleton-animation` → `--f12-skeleton-animation`, `--f-enter-animation` → `--f12-enter-animation`, `--f-pop-animation` → `--f12-pop-animation`, `--f-burst-animation` → `--f12-burst-animation`), aligning with `--f12-autocut-display` and `--f12-m-chars` so the `--f-*` prefix is reserved exclusively for public design tokens.
