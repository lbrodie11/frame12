  - `.f12-select-item:focus-visible`, `.f12-menu-item:focus-visible`: `outline: 2px solid var(--f-ink); outline-offset: -2px;`
  - `.f12-rng-btn:focus-visible`: `outline: 3px solid var(--f-ink); outline-offset: -6px;` (and `.f12-rng:not(:has(.f12-rng-ind)) .f12-rng-btn[aria-pressed="true"]:focus-visible { outline-color: var(--f-panel); }` pre-hydration).

### 2.3 Dialog Focus Restoration Across Engines
- **Finding Fixed in WP1:** In WebKit (Safari), clicking a `<button>` with a pointer does not move `document.activeElement` to the button by default. Consequently, when native `HTMLDialogElement.close()` ran, WebKit either left focus on `document.body` (if nothing was focused prior to clicking the trigger) or restored focus to whichever input happened to be focused before the user clicked `DialogTrigger`.
- **Fix (`registry/ui/dialog.tsx`):** `DialogTrigger` records `e.currentTarget` into `returnFocusRef` on activation, and `Dialog` records `document.activeElement` immediately before `showModal()` into `preOpenActiveRef`. When `<dialog>` closes via `Escape`, `DialogClose`, or backdrop click, `restoreFocus()` returns focus to `returnFocusRef.current` whenever post-close focus is `document.body`, inside the closed `<dialog>`, or reverted to `preOpenActiveRef.current` (while respecting any intentional consumer focus transfer to another element).
- **Verification:** Confirmed in `registry/tests/cross-browser.mjs` across **Chromium, Firefox, and WebKit** both when `#input-store` was focused prior to clicking `#gal-dialog-open` (`Escape` close) and on `DialogClose` button activation (`activeId === 'gal-dialog-open'`).

### 2.4 Nested-Overlay Portal Placement & Escape Behavior Inside `<Dialog>`
- **Portal Placement:** `SelectContent` (`registry/ui/select.tsx:129-135`) and `DropdownMenuContent` (`registry/ui/dropdown-menu.tsx:88-94`) resolve their portal container via `field?.containerEl?.closest('dialog, .f12-frame, .f12-sheet, .f12-theme-dark, .f12-theme-light, [data-theme]')`, portaling directly into the enclosing `<dialog>` element so floating menus/listboxes render inside the browser's top layer above the modal backdrop.
- **Escape Isolation:** When a `DropdownMenu` or `Select` is open inside an open `Dialog`, pressing `Escape` must dismiss **only** the open menu/listbox without closing the parent `<dialog>`. `DialogContent` attaches a document capture-phase `keydown` listener (`onDocKeyDownCapture`) before Radix `DismissableLayer` unmounts the `[role="listbox"]` or `[role="menu"]` node, setting `childPopupOpenOnEscapeRef.current = true` for that tick and calling `e.preventDefault()` on the `<dialog>` `cancel` event if triggered.
- **Verification:** Confirmed in `registry/tests/cross-browser.mjs` across **Chromium, Firefox, and WebKit**: `dlg.contains(menu) === true`, first `Escape` unmounts `[role="menu"]` while `dialog.open === true`, and second `Escape` closes `<dialog>` and restores focus to `#gal-dialog-open`.

### 2.5 Input Error Announcement Behavior
- Passing a non-empty `error` string to `<Input>` sets `aria-invalid="true"` on the `<input>`, renders `<p id={errorId} class="f12-error" role="alert">`, and appends `errorId` to `aria-describedby` alongside any hint ID and caller-supplied `aria-describedby` IDs.
- **Verification:** Confirmed in `registry/tests/unit.mjs` and `registry/tests/cross-browser.mjs` across Chromium, Firefox, and WebKit.

### 2.6 Chart Keyboard Scrubbing & Data Table Alternatives
- `ToneAreaChart` renders an interactive `<svg class="f12-chart-svg" role="img" tabIndex={0}>` supporting `ArrowLeft`, `ArrowRight`, and `Escape`.
- Scrubbing across points renders `<div class="f12-tip" role="status">` with the active point's label, primary series value, and comparison series value (when active).
- When `showTable` is enabled (`true` by default), `ToneAreaChart` also renders a collapsible `<details class="f12-tbl"><summary>View data table ({N} rows)</summary><table>...</table></details>` (`<th scope="col">` column headers and `<td>` row cells) directly below the SVG so keyboard and screen-reader users can inspect all raw tabular values without relying on SVG coordinate scrubbing.
