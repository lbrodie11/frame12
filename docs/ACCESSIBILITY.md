## 2. Deep-Dive Verification on WCAG 2.2 AA Focus Areas

### 2.1 Target Size (WCAG 2.2 SC 2.5.8 — Minimum 24×24 CSS px)
- **Measured Control Dimensions (Chromium, Firefox, WebKit):**
  - `Button` (`md`): `36px` height (`padding: 7px 14px`, `2.5px` border)
  - `Button` (`sm`): `29px` height (`padding: 4px 10px`, `2px` border)
  - `SegmentedControl` (`.f12-rng-btn`): `31px` height (`padding: 5px 11px`) with `2px` separator borders
  - `Input` (`.f12-input`): `38px` height (`padding: 7px 10px`, `2.5px` border)
  - `SelectTrigger` (`.f12-select-trigger`): `38px` height (`padding: 7px 12px`, `2.5px` border)
  - `SelectItem` / `DropdownMenuItem`: `32px` height (`padding: 6px 10px`)
  - `ToneBarList` row button (`.f12-bar-row`): `44px–52px` height with `10px` vertical gap
- All interactive controls exceed the WCAG 2.2 AA `24×24 CSS px` target size requirement.

### 2.2 Focus Visibility & Not Obscured (WCAG 2.2 SC 2.4.7 & 2.4.11)
- Every interactive control defines an explicit `:focus-visible` rule (`outline: 2.5px solid var(--f-focus); outline-offset: 2px` or `inset` equivalent inside constrained containers).
- `--f-focus` resolves to `#121212` against `#FFFFFF`/`#F3F2EE` in light mode (`18.7:1` / `17.1:1`) and `#FFD60A` (marker yellow) against `#0E0E0F`/`#19191A` in dark mode (`13.8:1` / `12.6:1`), exceeding the 3:1 non-text contrast requirement by more than 4×.
- `registry/tests/a11y.mjs` and `site/tests/site-verify.mjs` programmatically Tab through every focusable element on every route and assert a visible focus indicator and complete Tab cycle.

### 2.3 Dialog Focus Restoration Across Engines
- **Finding Fixed in WP1:** In WebKit (Safari), clicking a `<button>` with a pointer does not move `document.activeElement` to the button by default, causing native `HTMLDialogElement.close()` to leave focus on `document.body` instead of returning focus to the `DialogTrigger`.
- **Fix (`registry/ui/dialog.tsx`):** `DialogTrigger` records `e.currentTarget` into `returnFocusRef` on activation (and `setOpen(true)` falls back to `document.activeElement` for programmatic opens). When `<dialog>` closes via `Escape`, `DialogClose`, or backdrop click, `restoreFocus()` returns focus to the opener (`opener.focus({ preventScroll: true })`).
- **Verification:** Confirmed in `registry/tests/cross-browser.mjs` across **Chromium, Firefox, and WebKit** for both `Escape` dismissal and `DialogClose` button activation (`activeId === 'gal-dialog-open'`).

### 2.4 Nested-Overlay Escape Behavior
- When a `DropdownMenu` or `Select` is opened inside an open `Dialog`, pressing `Escape` must dismiss **only** the open menu/listbox without closing the parent `<dialog>`.
- `DialogContent` attaches a document capture-phase `keydown` listener (`onDocKeyDownCapture`) before Radix `DismissableLayer` unmounts the `[role="listbox"]` or `[role="menu"]` node, setting `childPopupOpenOnEscapeRef.current = true` for that tick and calling `e.preventDefault()` on the `<dialog>` `cancel` event if triggered.
- **Verification:** Confirmed in `registry/tests/cross-browser.mjs` across **Chromium, Firefox, and WebKit**: first `Escape` unmounts `[role="menu"]` while `dialog.open === true`; second `Escape` closes `<dialog>` and restores focus to `#gal-dialog-open`.

### 2.5 Input Error Announcement Behavior
- Passing a non-empty `error` string to `<Input>` sets `aria-invalid="true"` on the `<input>`, renders `<p id={errorId} class="f12-error" role="alert">`, and appends `errorId` to `aria-describedby` alongside any hint ID and caller-supplied `aria-describedby` IDs.
- **Verification:** Confirmed in `registry/tests/unit.mjs` and `registry/tests/cross-browser.mjs` across Chromium, Firefox, and WebKit.

### 2.6 Chart Keyboard Scrubbing & Data Table Alternatives
- `ToneAreaChart` renders an interactive `<svg class="f12-chart-svg" role="group" tabindex="0">` supporting `ArrowLeft`, `ArrowRight`, `Home`, `End`, and `Escape`.
- Moving the active point updates `<div class="f12-live" aria-live="polite" aria-atomic="true">` with the date/label, primary series value, and comparison series value (when active).
- Every `ToneAreaChart` also renders a collapsible `<details class="f12-tbl"><summary>View data table ({N} rows)</summary><table>...</table></details>` directly below the SVG so keyboard and screen-reader users can inspect all raw tabular values without relying on SVG coordinate scrubbing.
