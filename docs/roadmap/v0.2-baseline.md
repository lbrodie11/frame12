## 3. Confirmed Architectural Gaps & Technical Risks for v0.2.0

1. **Duplicate CSS in Individual Registry Item Payloads (Target: WP2)**
   - **Observed Fact:** In `registry/registry.json`, every individual component item (`sheet`, `panel`, `button`, etc.) currently lists `{"path": "styles/frame12.css", "type": "registry:file", "target": "styles/frame12.css"}` directly in its `files` array rather than declaring `registryDependencies: ["https://frame12.dev/r/frame12-styles.json"]` (or relative equivalent).
   - **Impact:** Installing 5 individual components sequentially overwrites `src/styles/frame12.css` 5 times and bloats each JSON payload by ~33 KB.
   - **Mitigation Plan (WP2):** Extract shared foundation dependencies (`frame12-styles`, `use-on-twos`, `button`) into `registryDependencies` while preserving offline/local-server testability in `scripts/smoke-install.mjs`.

2. **WebKit Pointer-Click Focus & `<dialog>` Focus Restoration (Fixed in WP1)**
   - **Observed Fact:** Unlike Chromium, WebKit on macOS does not move `document.activeElement` to a `<button>` when clicked with a pointer, so native `HTMLDialogElement.close()` either left focus on `document.body` or restored focus to a previously focused input rather than the clicked `DialogTrigger`.
   - **Resolution in WP1:** `DialogTrigger` captures `e.currentTarget` into `returnFocusRef` on click, `Dialog` records `document.activeElement` before `showModal()` into `preOpenActiveRef`, and `restoreFocus()` restores `returnFocusRef.current` whenever focus after `close()` is `document.body`, inside the closed dialog, or reverted to `preOpenActiveRef.current` (while preserving intentional consumer focus transfers). Verified across Chromium, Firefox, and WebKit in `registry/tests/cross-browser.mjs`.

3. **Keyboard Roving Focus & Focus Contrast on `SegmentedControl` (Fixed in WP1)**
   - **Observed Fact:** `SegmentedControl` (`role="group"` with `<button aria-pressed>`) previously lacked arrow-key navigation, put every button in the Tab sequence, and used `outline: 3px solid var(--f-marker)` (`1.41:1` contrast on unselected white buttons in light mode).
   - **Resolution in WP1:** Added roving `tabIndex` (`0` on the focused/selected button, `-1` on others), focus-only `ArrowLeft`/`ArrowRight`/`ArrowUp`/`ArrowDown`/`Home`/`End` navigation (with a modified-key guard so `Alt+Arrow` browser shortcuts are ignored and `Space`/`Enter` activates selection), and a `3px solid var(--f-ink); outline-offset: -6px` focus ring (`18.74:1` in light mode, `14.63:1` in dark mode, and automatically inverted by `.f12-rng-ind`'s `mix-blend-mode: difference` when selected). Verified across Chromium, Firefox, and WebKit.

4. **Missing Expressive/Quiet Hierarchy, Form Kit, and Feedback/Navigation Primitives for Full Applications (Target: WP3–WP5)**
   - **Observed Fact:** Building dense operational software (Developer Console, Workspace Settings, and Analytics blocks in WP6–WP8) alongside narrative storyboard views currently requires an explicit **Quiet** visual treatment (exposure-sheet/ledger presentation with 1px orthographic rules and subordinate groups that do not require sequential `C-01..C-0n` cut badges) as well as first-party form, feedback, loading, and navigation primitives (`Checkbox`, `RadioGroup`, `Switch`, `Textarea`, `Field`, `Tabs`, `Alert`/`Notice`, `Toast`, `Skeleton`, `EmptyState`, `Breadcrumb`, and `Pagination`).
   - **Mitigation Plan (WP3–WP5):** Establish the Expressive/Quiet design grammar and non-color semantic status system in **WP3**, implement the Essential Form Kit + `Tabs` in **WP4**, and implement the Feedback, Loading, and Navigation Kit in **WP5** following the Two-Tier Hybrid Foundation defined in `docs/architecture/primitive-foundation.md`.

## 4. Primitive-Foundation Recommendation Summary

Full analysis is recorded in [`docs/architecture/primitive-foundation.md`](../architecture/primitive-foundation.md):
- **Tier 1 (Default — Native HTML + React Hooks):** Used for 17 of 19 current components and the planned WP4–WP5 primitives (`<dialog>`, `<details>`, `<button>`, `<input>`, `<textarea>`, `<fieldset>`, `<nav>`, `<table>`, inline `<svg>`). Zero external runtime dependencies, 100% SSR deterministic, and immune to `shadcn` CLI AST codemods.
- **Tier 2 (Positioned Floating Overlays — Isolated `@radix-ui/*` Adapters):** Retained for `Select` and `DropdownMenu`, strictly adhering to the direct `.f12-btn` trigger rendering pattern so `shadcn init -d` (`base-nova` style) never rewrites `asChild` to Base UI's `render` prop.
