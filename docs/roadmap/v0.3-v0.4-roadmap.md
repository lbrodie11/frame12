# FRAME/12 — Strategic Product Roadmap: `v0.3` & `v0.4`

> **Status:** Post-`v0.2.0` Strategic Plan  
> **Baseline:** `v0.2.0` (31 components · 1 hook · 3 application blocks · 8-rule design grammar with static AST checker + Playwright a11y/DOM verification · 4-condition × 6-task guardrail & reference fixture suite · published in the official `shadcn` registry index as `@frame12`)  
> **Scope:** Product strategy, open-source commitment, component & block roadmap, and scope classification for `v0.3` and `v0.4`

---

## 1. Executive Thesis: From Cult Artifact to Indispensable Frontend Toolkit

With `v0.2.0`, FRAME/12 proved four things that almost never coexist in the same UI repository:

1. **A genuinely original visual identity** (90s shōnen/seinen manga ink rules, asymmetric chamfered hero cuts, SVG screentone data graphics, and 12fps "on twos" stepped motion) that cannot be mistaken for default Tailwind/shadcn boilerplate.
2. **Production-grade engineering discipline** (WCAG 2.2 AA contrast in both Paper Light and Flashback Dark, zero axe-core violations, roving keyboard navigation, `forced-colors: active` support, pre-hydration zero-FOUC theme scripting, and `0.000` CLS across desktop and 320px viewports).
3. **Full-page operational sufficiency** via three copy-pasteable `registry:block` reference applications (`DeveloperConsole`, `WorkspaceSettings`, `AnalyticsDashboard`).
4. **Machine-enforced AI generation** via a static AST/JSX/CSS design-grammar checker (`scripts/check-frame12.mjs`), synchronized TypeScript/doc contracts (`scripts/check-doc-sync.mjs`), and a 4-condition × 6-task (`24`-screen) guardrail and reference fixture suite (`eval/agent-eval/run-eval.mjs`) where the skill-plus-checker condition (`c4-frame12-skill-plus-checker`) passes `6 / 6` (`100%`) reference screens with `0` grammar violations while catching `48` seeded drift violations across the negative-control conditions.

### The Strategic Gap After `v0.2.0`

Today, a developer who discovers FRAME/12 is immediately struck by the aesthetic, explores the live blocks, and can install components directly via the official `@frame12` namespace (`npx shadcn@latest add @frame12/frame12`). However, when they sit down to build a **complete daily-driver SaaS product, AI agent workbench, or internal tool**, they hit three practical friction points:

- **Interaction Completeness (`v0.3` Theme: *Daily-Driver Application Depth*):** Real applications need command palettes (`⌘K`), slide-over drawers for inspection without losing table context, date-range pickers, popovers, collapsible accordions, and multi-line/stacked chart comparisons. If a team has to drop back to unstyled Radix primitives and hand-write 2px ink borders and asymmetric chamfers for those 8 primitives, adoption slows down.
- **Zero-Friction Scaffolding & Editor Feedback (`v0.3`–`v0.4` Theme: *Instant DX & Live Grammar Guardrails*):** Running `npx shadcn@latest add @frame12/<name>` is fast, but teams starting a new app want a single `npx create-frame12-app` command, a zero-config Tailwind v4 `@plugin` / CSS preset, and real-time IDE/MCP feedback when an AI coding agent violates a cut or marker rule.
- **Owning a Defining Category (`v0.4` Theme: *The Canonical UI System for AI Agents & Developer Tools*):** Every AI startup and developer-tooling team in 2026 is building trace inspectors, tool-call approval queues, prompt diff viewers, and streaming run logs. Almost all of them look identical. FRAME/12's sequential cut numbering (`C-01 -> C-02 -> C-03`), high-contrast ink hierarchy, and stepped 12fps cadence are **uniquely suited to represent discrete agent steps, tool executions, and human-in-the-loop gates**.

## 2. Open-Source Commitment & Licensing Boundary

FRAME/12 is built on a transparent, developer-first open-source foundation:

- **Existing MIT-licensed components remain MIT-licensed.** All 31 components shipped in `v0.1.0` and `v0.2.0` remain permanently available under the [MIT License](../../LICENSE).
- **The existing three application blocks remain available under MIT.** `DeveloperConsole` (`@frame12/developer-console`), `WorkspaceSettings` (`@frame12/workspace-settings`), and `AnalyticsDashboard` (`@frame12/analytics-dashboard`) remain free, copy-pasteable MIT-licensed reference blocks.
- **The existing style system, tokens, hooks, agent skill, and grammar checker remain open source.** `registry/styles/frame12.css`, `registry/styles/frame12-tailwind.css`, `use-on-twos`, `skills/frame12/SKILL.md`, and `scripts/check-frame12.mjs` remain open source under MIT (bundled font binaries remain under the SIL Open Font License 1.1).
- **The core component foundation remains publicly usable and open source.** Our ongoing direction is to keep the core FRAME/12 component primitives, design tokens, and public `@frame12` registry open source and usable without gated dependencies.
- **Future commercial products, if introduced, will be separately identified and licensed.** If optional commercial workflow kits, backend reference integrations, or enterprise extensions are introduced in the future, they will live outside the MIT core, carry explicit separate licensing, and never retroactively restrict existing MIT code.
- **Nobody needs to purchase a premium product to use the existing FRAME/12 design system.** Developers and teams can adopt, customize, and ship production applications with the FRAME/12 design system, its 31 components, its 3 flagship blocks, and its agent skill at zero cost.

### Roadmap Scope Classification Labels

To make the boundary between open-source core work, free examples, exploratory research, and potential future commercial extensions unambiguous, every roadmap item below carries one of four explicit labels:

| Classification Label | Meaning |
| :--- | :--- |
| **`[Open-Source Core — MIT]`** | Planned open-source UI primitive, chart, hook, style token, or CLI/checker enhancement intended for the public MIT repository and `@frame12` registry. |
| **`[Free Application Example — MIT]`** | Planned open-source `registry:block` showcase powered by deterministic local fixtures, copy-pasteable under the MIT License. |
| **`[Experimental / Research Candidate]`** | Exploratory technical direction or developer-experience tool under evaluation; not yet an approved implementation commitment. |
| **`[Potential Commercial Extension — Subject to Validation]`** | Separate optional commercial product hypothesis under customer discovery and validation; does **not** exist today and is not required to use FRAME/12. |

> [!NOTE]
> Unbuilt items in this document represent planned or exploratory product direction, not shipped software or guaranteed release commitments. See [`adoption-measurement-spec.md`](./adoption-measurement-spec.md) for privacy-conscious adoption measurement guidelines.

## 4. Screentone Data Visualization Suite (`v0.3`)

> **Classification:** **`[Open-Source Core — MIT]`**

FRAME/12's SVG screentone charts (`ToneAreaChart`, `ToneBarList`, `ToneSpark`) are one of its strongest visual differentiators. In `v0.3`, we plan to expand the open-source chart suite from **3 -> 6 data-visualization primitives** so teams never have to reach for an external charting library that clashes with the monochrome ink grammar:

1. **`ToneMultiSeriesChart` (`tone-multi-series-chart`) — `[Open-Source Core — MIT]`:**
   - Supports 2–4 concurrent series without rainbow color palettes by pairing **distinct SVG fill/stroke textures**:
     - Series A: Solid 2.5px ink stroke + `tone-dots-16` area fill
     - Series B: Crisp dashed ink stroke (`6 4`)
     - Series C: Diagonal line-hatch (`tone-hatch-45`) or dotted cadence (`2 3`)
   - Includes interactive keyboard-navigable crosshair scrubber (Left/Right arrow keys step through time buckets at 12fps and announce values via `aria-live`).
2. **`ToneStackedBarChart` (`tone-stacked-bar-chart`) — `[Open-Source Core — MIT]`:**
   - Vertical or horizontal time-bucketed bar chart for comparing status breakdowns over time (e.g., `2xx` solid ink vs. `4xx` coarse screentone vs. `5xx` cross-hatch with optional marker-yellow anomaly cap on the peak bucket).
3. **`ToneHeatmap` / `CadenceGrid` (`tone-heatmap`) — `[Open-Source Core — MIT]`:**
   - A 24x7 or 52-week density matrix where intensity is encoded through **4 stepped screentone dot densities** (`0%` paper, `15%` fine dots, `45%` medium dots, `80%` heavy dots, `100%` solid ink) instead of low-contrast color gradients—guaranteeing WCAG AA legibility and `forced-colors` resilience.

### 6.2 Agentic UI Primitives (`registry:ui`)

> **Classification:** **`[Open-Source Core — MIT]`**

Ship 4 purpose-built open-source components for AI products, coding assistants, and agentic workflows:

1. **`TraceTimeline` (`trace-timeline`) — `[Open-Source Core — MIT]`:**
   - Displays multi-step agent execution graphs (`THOUGHT -> TOOL CALL -> OBSERVATION -> SYNTHESIS`) as a vertical comic-strip sequence where each step carries a sub-cut label (`STEP 01 · 140ms`), status tag, collapsible JSON payload, and 12fps active step pulse.
2. **`ApprovalGate` (`approval-gate`) — `[Open-Source Core — MIT]`:**
   - Human-in-the-loop confirmation card for high-stakes tool calls (e.g., `DROP TABLE`, production deploy, outbound wire transfer). Uses the asymmetric chamfered hero frame (`chamfer`) and the **single permitted `--f12-marker` yellow accent** on the `AWAITING OPERATOR APPROVAL` badge, with keyboard-accessible `Approve (Enter)` / `Reject (Esc)` actions and inline parameter diffing.
   - **Security Boundary:** `ApprovalGate` is a **client-side presentation primitive**. Security-sensitive approvals must always be validated and enforced by a trusted server, never solely by a client-side React component.
3. **`PromptComposer` (`prompt-composer`) — `[Open-Source Core — MIT]`:**
   - Multi-line command input with context-attachment chips (`Tag`), model/mode `SegmentedControl`, token-budget meter (`ToneSpark`), and keyboard submit (`⌘Enter`).
4. **`StreamingLog` (`streaming-log`) — `[Open-Source Core — MIT]`:**
   - Terminal/event stream viewer quantized to `useOnTwos` (83.33ms / 12fps frame ticks) so high-velocity token or log streams update in crisp, readable editorial frames rather than jittery 60fps layout thrashing.

## 7. Flagship Application Blocks & Potential Commercial Boundary (`v0.4`)

To demonstrate the `v0.3` and `v0.4` primitives working together at full scale, we plan **two additional free open-source `registry:block` reference applications** (expanding the free MIT block catalog from 3 -> 5 flagship blocks), alongside customer validation for a potential separate commercial workflow kit.

### 7.1 `AgentReviewConsole` (`@frame12/agent-review-console`) — Free Open-Source Block

> **Classification:** **`[Free Application Example — MIT]`**

- **Domain:** Autonomous AI Engineering & Tool-Call Governance Workbench (demonstrated with deterministic local fixtures).
- **Planned Open-Source Scope:**
  - Combines `Sheet`, `Scene`, `Panel` (`chamfer` on `C-01` pending approval gate), `TraceTimeline`, `ApprovalGate`, `CodeBlock` (unified diff view), `CommandPalette`, `Drawer`, `ToneMultiSeriesChart` (token throughput & tool latency), and `ToastProvider`.
  - Ships with deterministic local fixture runs (`Populated`, `Loading`, `Empty`, `Error`) and full interactive flows: stepping through an agent's multi-tool execution trace, inspecting proposed code/SQL diffs in a slide-over `Drawer`, approving or rejecting a gated production action in `C-01`, and replaying a deterministic prompt run.
  - Permanently free and MIT-licensed as part of the public `@frame12` registry.

### 7.2 Potential Separate Commercial Extension: *FRAME/12 Studio — Agent Review Kit*

> **Classification:** **`[Potential Commercial Extension — Subject to Validation]`**  
> **Status:** Research & customer-validation candidate only — **not** an existing product and **not** an approved implementation commitment.

While the open-source `agent-review-console` block provides the complete UI composition with deterministic local fixtures under MIT, engineering teams deploying human-in-the-loop agent approvals into production face backend, state-integrity, and framework-integration requirements that go beyond a static frontend block.

We are evaluating whether there is validated customer demand for a **separate, optional commercial extension** (**FRAME/12 Studio — Agent Review Kit**). Customer discovery prioritizes **Vercel AI SDK + Next.js App Router** first, treats **Model Context Protocol (MCP)** tool calls as a cross-cutting integration scenario (recognizing MCP as a tool-integration protocol rather than a standalone orchestration runtime), and evaluates **LangGraph** (starting with its TypeScript SDK, and Python-backed workflows if demand warrants) next.

Possible capabilities under research include:

- **Tested adapters for real agent-framework event streams** (starting with Vercel AI SDK + Next.js App Router streaming tool calls and MCP tool-call metadata, and evaluating LangGraph interrupt/resume streams based on customer demand)
- **Reference backend for version-bound approvals** (cryptographically binding an operator's approval decision to the exact tool name, schema version, and canonicalized argument payload hash so mutated payloads cannot execute under a stale approval)
- **Durable approval state transitions** (`PENDING -> APPROVED | REJECTED | EXPIRED | REVOKED -> EXECUTED` with audit-log persistence)
- **Replay and duplicate-action protection** (idempotency keys and single-use execution tokens preventing double-submission or replay attacks)
- **Expiration and revocation handling** (TTL enforcement on pending tool approvals and operator-initiated revocation before execution)
- **Automated integration and security tests** (verifying payload-tampering rejection, expired-token rejection, and concurrent-approval race handling)
- **End-to-end reference workflows** (connecting streaming agent pauses, operator review notifications, and resumed execution)
- **Production integration documentation** (deployment checklists, threat model notes, and auth boundary guides)

> [!IMPORTANT]
> **Critical Security & Scope Note:**
> 1. The capabilities listed above for **FRAME/12 Studio — Agent Review Kit** are **research candidates subject to customer validation, not approved implementation commitments**. No commercial adapters, reference approval servers, or proprietary source code are being built at this stage.
> 2. **Security-sensitive approvals must be enforced by a trusted server, not only a client-side React component.** Any production human-in-the-loop gate must verify authorization, payload integrity, expiration, and idempotency on the server before executing privileged tools.
> 3. If a commercial extension is ever built, it will be maintained in a separate private repository and licensed separately; the open-source `agent-review-console` block and all core FRAME/12 primitives will remain free under MIT.

## 8. Non-Negotiable Quality & Invariant Gates for `v0.3` and `v0.4`

Every component and block added in `v0.3` and `v0.4` must pass the exact engineering bar established in `v0.2.0` before merge:

1. **The 8 Design-Grammar Rules (Static Checker + Browser/Review Verification):**
   - **Statically enforced by `npm run lint:frame12` (`scripts/check-frame12.mjs`, `0` violations):** `color-literal` / `font-literal`, `illegal-gutter` (`12px` / `20px` / `32px`), `cut-order` & `explicit-cut-in-autocut` (sequential `C-01..C-NN` cut numbering), `marker-misuse` (`--f-marker` paired strictly with `--f-marker-ink` or inked peak dots), and `raw-shadcn-import`.
   - **Verified by runtime hooks (`useOnTwos`), Playwright DOM/accessibility checks (`site/tests/site-verify.mjs`, `registry/tests/verify.mjs`), and code review:** 12fps stepped motion on twos (`0ms` under `prefers-reduced-motion: reduce`), Flashback dark mode & WCAG AA contrast, zero external chart/animation libraries, and visual grammar review (no blurred drop shadows, no spring physics, and disciplined hero framing).
2. **100% AST Contract Synchronization:** Enforced by `npm run doc:check`. Every exported `*Props` interface in `registry/ui/*.tsx` and `registry/blocks/*.tsx` must match `site/src/lib/catalog.ts`, `skills/frame12/references/components-and-adapters.md`, and `site/public/r/*.json`.
3. **Backward-Compatible Semver Evolution:** Enforced by `node scripts/check-api-compat.mjs` against `v0.2.0` contracts unless an explicit major-version migration codemod is provided.
4. **Cross-Browser & Accessibility Verification:** Zero `@axe-core/playwright` violations, WCAG AA contrast (`>= 4.5:1` body, `>= 3:1` large text) in both Paper Light and Flashback Dark, visible keyboard focus across every tab stop, `forced-colors: active` resilience, and zero horizontal overflow at `1280px`, `768px`, `390px`, and `320px` across Chromium, Firefox, and WebKit.
5. **Guardrail & Reference Fixture Evaluation:** Every new component and rule must be covered by the 4-condition × 6-task evaluation harness (`node eval/agent-eval/run-eval.mjs`), maintaining a `100%` (`6 / 6`) pass rate in the skill-plus-checker condition (`c4-frame12-skill-plus-checker`) and verifying negative-control violation detection.
